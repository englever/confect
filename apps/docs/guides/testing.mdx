`@confect/test` wraps [`convex-test`](https://docs.convex.dev/testing) with Effect-native APIs. It provides a `TestConfect` service that lets you call your Confect functions using refs, run arbitrary mutation-context code for test setup, and test with user identities.

## Installation

<CodeGroup>

```bash pnpm
pnpm add -D @confect/test convex-test @effect/vitest
```

```bash npm
npm install -D @confect/test convex-test @effect/vitest
```

```bash yarn
yarn add -D @confect/test convex-test @effect/vitest
```

```bash bun
bun add -D @confect/test convex-test @effect/vitest
```

</CodeGroup>

## Setup

Create a `TestConfect.ts` file that configures the test layer with your generated runtime schema, generated Convex schema definition, and Convex modules. Both schemas are emitted by `confect codegen` from `confect/tables/*.ts`; you never edit them by hand.

```ts test/TestConfect.ts
/// <reference types="vite/client" />

import { TestConfect as TestConfect_ } from "@confect/test";

import confectSchema from "./confect/_generated/schema";
import convexSchema from "./confect/_generated/convexSchema";

export const TestConfect = TestConfect_.TestConfect<typeof confectSchema>();

export const layer = TestConfect_.layer(
  confectSchema,
  convexSchema,
  import.meta.glob("./convex/**/!(*.*.*)*.*s"),
);
```

Every time the `TestConfect` layer is constructed, a new test database is created. If you want a clean database for each test, provide the layer on a per-test basis (as shown below). If you want to share state across tests in a describe block, you can provide the layer at a higher scope instead.

## Writing tests

Use `@effect/vitest`'s `it.effect` to write effectful tests. Yield `TestConfect` from the service, then call your functions using refs.

```ts test/notes.test.ts
import { describe, it } from "@effect/vitest";
import { assertEquals } from "@effect/vitest/utils";
import * as Effect from "effect/Effect";

import refs from "./confect/_generated/refs";
import * as TestConfect from "./TestConfect";

describe("notes", () => {
  it.effect("can insert and list notes", () =>
    Effect.gen(function* () {
      const c = yield* TestConfect.TestConfect;

      yield* c.mutation(refs.public.notes.insert, {
        text: "Hello",
      });

      const notes = yield* c.query(refs.public.notes.list, {});

      assertEquals(notes.length, 1);
      assertEquals(notes[0]?.text, "Hello");
    }).pipe(Effect.provide(TestConfect.layer)),
  );
});
```

## Calling functions

`TestConfect` provides `query`, `mutation`, and `action` methods that accept a ref and args, returning an `Effect` with the decoded result.

```ts
Effect.gen(function* () {
  const c = yield* TestConfect.TestConfect;

  const notes = yield* c.query(refs.public.notes.list, {});

  const noteId = yield* c.mutation(refs.public.notes.insert, {
    text: "Hello",
  });

  const result = yield* c.action(refs.public.random.getNumber, {});
});
```

## Typed errors

When a ref's spec declares an `error` schema, the decoded error is added to the error channel of `query`, `mutation`, and `action` alongside `ParseError`. See [Error Handling](/server/error-handling) for how to declare error schemas.

```ts
import { describe, it } from "@effect/vitest";
import { assertFailure } from "@effect/vitest/utils";
import type { GenericId } from "convex/values";
import * as Effect from "effect/Effect";

import { NoteNotFound } from "./confect/notes.spec";
import refs from "./confect/_generated/refs";
import * as TestConfect from "./TestConfect";

describe("notes", () => {
  it.effect("returns NoteNotFound for a missing id", () =>
    Effect.gen(function* () {
      const c = yield* TestConfect.TestConfect;

      const result = yield* c
        .query(refs.public.notes.getOrFail, {
          noteId: "missing" as GenericId<"notes">,
        })
        .pipe(Effect.result);

      assertFailure(result, new NoteNotFound({ noteId: "missing" }));
    }).pipe(Effect.provide(TestConfect.layer)),
  );
});
```

## Running setup code

Use `run` to execute arbitrary code with mutation-context services (like `DatabaseWriter`) for test setup. When the handler returns a value, pass a `Schema` as the second argument for decoding.

```ts
import { Id } from "./confect/_generated/id";
import { DatabaseWriter } from "./confect/_generated/services";

Effect.gen(function* () {
  const c = yield* TestConfect.TestConfect;

  const noteId = yield* c.run(
    Effect.gen(function* () {
      const writer = yield* DatabaseWriter;

      return yield* writer.table("notes").insert({ text: "seed data" });
    }),
    Id("notes"),
  );
});
```

When the handler returns `void`, the second argument can be omitted.

```ts
Effect.gen(function* () {
  const c = yield* TestConfect.TestConfect;

  yield* c.run(
    Effect.gen(function* () {
      const writer = yield* DatabaseWriter;

      yield* Effect.forEach(items, (item) =>
        writer.table("notes").insert(item),
      );
    }),
  );
});
```

## Testing with user identity

Use `withIdentity` to scope function calls to a specific user identity.

```ts
Effect.gen(function* () {
  const c = yield* TestConfect.TestConfect;

  const asUser = c.withIdentity({
    subject: "user-123",
    tokenIdentifier: "https://example.com|user-123",
    email: "user@example.com",
  });

  const identity = yield* asUser.query(refs.public.auth.getIdentity, {});
});
```

## Testing HTTP endpoints

Use `fetch` to test your [HTTP API](/server/http-api) endpoints.

```ts
Effect.gen(function* () {
  const c = yield* TestConfect.TestConfect;

  const response = yield* c.fetch("/api/get-first");
  const body = yield* Effect.promise(() => response.json());
});
```

### Register component test kits

Pass an options object with a `register` callback as the fourth argument to `TestConfect.layer`. It runs synchronously during layer construction, after the test backend exists and before the service is available. The callback receives a registration function for the component's Convex schema and module loaders.

```ts test/TestConfect.ts
import { TestConfect } from "@confect/test";
import { register } from "@example/counter/testing";
import applicationSchema from "./confect/_generated/schema";
import convexSchema from "./confect/_generated/convexSchema";

export const layer = TestConfect.layer(
  applicationSchema,
  convexSchema,
  import.meta.glob("./convex/**/!(*.*.*)*.*s"),
  {
    register: (registerComponent) => {
      register(registerComponent, "counter");
    },
  },
);
```

Use the same component path as the installation in `convex.config.ts`. Register nested components separately with their full path, such as `"counter/child"`. Once registered, call bound references with `query`, `mutation`, and `action`. You can also register after setup with the existing effectful `registerComponent` method.

### Fetch mounted component routes

Add `httpMounts` to describe the routes your application exposes. TestConfect does not evaluate `convex.config.ts`. Each descriptor pairs a registered `componentPath` with its `httpPrefix`.

```ts
const layer = TestConfect.layer(
  applicationSchema,
  convexSchema,
  applicationModules,
  {
    register: (registerComponent) => {
      register(registerComponent, "first");
      register(registerComponent, "second");
    },
    httpMounts: [
      { componentPath: "first", httpPrefix: "/email" },
      { componentPath: "second", httpPrefix: "/other-email" },
    ],
  },
);

const program = Effect.gen(function* () {
  const c = yield* TestConfect.TestConfect<typeof applicationSchema>();
  return yield* c.fetch("/email/webhook", { method: "POST", body: "payload" });
}).pipe(Effect.provide(layer));
```

`fetch` selects the longest matching prefix at a path segment boundary. `/email/webhook` and the bare `/email` path match `/email`; `/emails/webhook` does not. The bare-prefix behavior can differ from Convex's trailing-slash mount routing. Trailing slashes on prefixes are ignored. Each prefix must be unique and start with `/`, without a query or fragment. Unmatched requests use the application's HTTP module as before. A mounted request does not require an application HTTP module. For a nested component, use its full host-visible prefix, such as `/parent/child`. This explicit table selects mounts before application routes; it does not reproduce Convex's full configuration and route precedence.

The selected component receives its own action context. Route lookup uses the path after the prefix, while the handler receives the full mounted request URL. During HTTP module construction and handler execution, `CONVEX_SITE_URL` is the application's site URL plus the mount prefix. Set the application's `CONVEX_SITE_URL` before fetching if you need a specific origin; otherwise TestConfect uses `https://some.convex.site`. The previous environment value is restored after the request, including when construction fails. `withIdentity` accessors use the same mounts; components still have no application auth capability.

### Construct a router for each mount

HTTP layers can read configuration while their module is constructed. ES imports cache modules across installations and tests. For two mounts of the same component, provide a module loader that constructs a fresh router. Keep the router factory in a separate module from the production HTTP entry point:

```ts src/testing.ts
import type { TestConfect } from "@confect/test";
import schema from "./convex/schema";

const modules = import.meta.glob("./convex/**/!(*.*.*)*.*s");

export const register = (
  registerComponent: TestConfect.RegisterComponent,
  name: string,
) => {
  registerComponent(name, schema, {
    ...modules,
    "./convex/http.ts": () =>
      import("./confect/httpFactory").then(({ makeHttp }) => ({
        default: makeHttp(),
      })),
  });
};
```

`makeHttp` must construct `HttpRouter.forSchema(componentSchema)(routes)` and any configuration-dependent route layers on each call. The production `confect/http.ts` can export `makeHttp()` as its default. TestConfect caches each mount's resulting router, including construction failures. A plain dynamic import of an already constructed router cannot provide separate construction-time configuration for two mounts.

<Warning>
  Mounted HTTP tests share the process environment. Fetches through one layer,
  including its identity accessors, run sequentially. Other layers and
  concurrent queries, mutations, or actions can still observe the temporary
  environment. Component modules can also see application environment variables.
  Run tests that need environment isolation on a local Convex backend.
</Warning>

The mounted bridge buffers request and response bodies and reconstructs response headers. It does not test streaming or repeated response headers faithfully. `originalUrl` retains the mount path and query, but its origin comes from the test site URL, not a real incoming connection. Module imports that already captured configuration keep those values. Use local-backend tests for behavior that depends on these differences.

## Testing scheduled functions

`TestConfect` provides helpers for advancing scheduled functions in tests.

```ts
Effect.gen(function* () {
  const c = yield* TestConfect.TestConfect;

  yield* c.finishInProgressScheduledFunctions();

  yield* c.finishAllScheduledFunctions(() => {
    vi.advanceTimersByTime(5000);
  });
});
```
